# Touchscreen Gesture Authentication 毕业设计上下文总结

整理日期：2026-11-15

## 1. 当前目标

用户已从 Gesture Authentication 的多个候选方向中，选定**触屏手势认证（Touchscreen Gesture Authentication）**作为毕业设计方向，计划设计并实现一个认证系统。

最初的研究动机：

- 相比九宫格手势解锁，不只检查手势形状，还检查用户执行手势的方式，希望降低被他人观察后冒充的风险。
- 手势内容可以更自由、多样，但“降低字典爆破风险”主要应由形状这一知识因子论证；速度、压力、节奏等行为特征主要用于提高模仿难度。
- 需要解决的核心矛盾：本人每次画出的轨迹不可能完全一样，系统既要容忍自然差异，又要拒绝冒用者。

## 2. 当前候选系统架构

系统暂时按两个串联模块理解：

1. **手势内容（形状）识别模块**
   - 判断画出的是否为注册的手势类别。
   - 当前倾向于作为硬门槛：手势类别不同，直接拒绝，不进入下一步。
   - 同一类别但存在轻微形状和轨迹差异时，应保留合理容差。

2. **轨迹动力学 / 每用户行为验证模块**
   - 当前重点特征为速度、压力，节奏也在讨论范围内。
   - 判断“执行这个动作的方式是否像本人”，输出定量相似度分数，再通过阈值作出通过或拒绝的决定。
   - 这是目前认为的核心模块，也是主要难点。

因此，“两次画出不同类别的手势仍通过”不是当前方案的目标；“同一手势类别下，本人每次轨迹细节不同但仍可能通过”才是需要实现的容错能力。若只识别形状，就接近九宫格解锁的扩展，无法体现行为认证的主要价值。

## 3. 认证与评估中的关键认识

- 认证不是逐点比较两条轨迹是否完全重合，而是计算相似度并进行阈值判定。
- 本人存在自然波动，因此误拒率（FRR）通常不可能绝对为零；需要在 FAR 与 FRR 之间权衡。
- 正式评估应考虑 open-set、跨会话测试，并报告 FAR、FRR、EER 及 ROC/DET 等指标。
- 为让 FAR 有说服力，后续需要考虑冒用者和主动模仿数据，而不只是随机拿其他用户的数据充当攻击。
- 不应把同一次采集的数据随机拆分后同时用于训练和测试，否则可能高估效果。

## 4. 单笔与多笔手势的讨论

导师询问手势是“一条连续长线”还是“多条分开的线”，并表示后一种更容易，可以逐条评估。当前将其理解为：**多笔手势在逐笔对齐和打分方面更容易，但用户尚未明确最终采用哪一种。**

多笔方案可能更容易评估的原因：

- 每笔序列更短，对齐误差不容易跨笔累积。
- 每笔的速度、压力曲线相对干净，类内变化可能更易建模。
- 可以获得单笔方案没有的笔间停顿、每笔耗时等节奏特征。
- 可以逐笔打分后融合，某一笔的局部异常不一定导致整个手势失败。

但多笔不等于简单地把多笔独立打分后平均。还需要保留笔序、笔间间隔、各笔相对位置等全局约束，否则攻击者可能逐笔模仿。多笔方案还会增加笔画分割和分数融合的工程量。

## 7. 当前直接任务

先进行一个小规模测试，验证**速度和压力能被采集到多准确**，然后再决定认证方法。

测试可重点检查：

- 不同设备上的触摸采样率、时间戳稳定性和噪声。
- 压力值是真实变化，还是固定值、模拟值或设备相关值。
- 同一用户重复同一手势时，速度和压力的自然波动范围。
- 不同用户之间是否出现初步可分性。
- 若压力不可用，是否能仅依靠速度及其他可可靠采集的特征继续设计。

Android 端后续可调查 `MotionEvent` 提供的坐标、事件时间、压力、接触面积和历史采样点等字段，但具体实现尚未开始。
